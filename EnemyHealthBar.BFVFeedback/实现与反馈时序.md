# BFV 命中/击杀反馈：实现与反馈时序

> 0.2.0 / 2026-11-17。配套 README、[说明.md](说明.md) 和
> [方案文档](../../../gtfo-bfv-feedback/方案-配合敌人血条mod.md)。
> 本文回答两件事：代码怎么接的；每一种音效/UI 在什么时刻出现。

---

## 1. 一句话架构

```text
本地 BulletDamage / MeleeDamage
  └─ 只读前缀 → BfvImpactContext（敌人、EnemyType、HealthMax、EyePosition、limb 类型、frame）
CrosshairGuiLayer.ShowHitIndicator
  └─ 前缀 → 命中线 + 命中音；成功时抑制原版
CrosshairGuiLayer.ShowDeathIndicator
  └─ 前缀 → 击杀线 + 击杀音 + 独立确认音 + 头顶图标；成功时抑制原版
CellSound.Post(uint) / (uint, Vector3)
  └─ 前缀 → 静音原版两个本地 indicator
EnemyHitApi.HitRegistered
  └─ 只做日志/联调核对，不决定反馈
```

- **不写血量、不发网络包、不改敌人数据**；命中上下文只读。
- 只影响安装者本机、只看本地玩家自己的命中/击杀。
- 事件主源是游戏自己的本地命中/击杀指示；`EnemyHitApi` 只做诊断/兜底。

## 2. 代码模块

| 文件 | 职责 |
| --- | --- |
| `Plugin.cs` | BepInPlugin / 硬依赖父 0.4.0 / 配置 / Harmony 注册 / 卸载 |
| `BfvRuntime.cs` | 唯一 IL2CPP 注入的 MonoBehaviour；只保留无复杂参数的 Unity 生命周期与转发方法 |
| `BfvController.cs` | 全部反馈逻辑：命中/击杀事件、队列、投影、绘制、音频调度 |
| `BfvImpactContext.cs` | `BulletDamage`/`MeleeDamage` 只读前缀保存命中上下文；不计算伤害 |
| `BfvPatches.cs` | `ShowHitIndicator` / `ShowDeathIndicator` / `CellSound.Post` 前缀 |
| `BfvAudio.cs` | WAV 解析、素材回落、高通、击杀确认音、WinMM 调度 |
| `WinMmPlayer.cs` | 8 个 WinMM `waveOut` voice；tanh 软限幅；48 kHz mono PCM16 |
| `BfvIcons.cs` | PNG → Texture2D 缓存；7 张命中线/击杀图标 |
| `Core/BfvPolicy.cs` | 纯 C# 档位、cue 回落、marker 规则、alpha/尺寸/clamp |
| `Core/BfvColor.cs` | `#RRGGBB(AA)` 解析 |
| `Core/BfvTypes.cs` | 档位/命中类型/风格枚举 |

### 2.1 为什么 `BfvRuntime` 很薄

IL2CPP 的 `ClassInjector` 会扫描注入类的每个方法。之前把 `BfvConfig`、`System.Type`、
`EnemyHitInfo` 等托管类型直接放进 `BfvRuntime`，导致 `ConvertMethodInfo` 空引用、插件加载失败。
现在：

- `BfvRuntime` 只保留 `IntPtr` 构造、`Update/OnGUI/OnDestroy` 和
  `Vector3/bool/uint` 参数的转发方法；
- 复杂逻辑全部在非注入的 `BfvController`；
- `BfvBootstrap` 用静态字段把配置和插件目录交给 `BfvRuntime`，避免复杂方法参数。

### 2.2 命中上下文（只读）

`BfvImpactContext.Record` 在 `BulletDamage`/`MeleeDamage` 前缀执行：

- 仅当 `sourceAgent == PlayerManager.GetLocalPlayerAgent()` 且 `health > 0`；
- 读取 `damage.Owner`、`EyePosition`、`EnemyData.EnemyType`、`HealthMax`、`DamageLimbs[limbID].m_type`；
- 写入一个 16 项环形缓冲，带 `frame`；`ShowHitIndicator/ShowDeathIndicator` 按位置/帧匹配；
- **不计算伤害、不写血量、不触发死亡**；异常全部吞掉，不破坏伤害调用。

## 3. 音效出现时机

### 3.1 命中音

| 触发 | 文件 | 条件 | 音色行为 |
| --- | --- | --- | --- |
| 普通命中 | `audio/bf5/hit.wav`（BF1 风格：`audio/bf1/hit.wav`） | 非弱点、非护甲 | 白 X 同时出现 |
| 弱点命中 | `audio/bf5/weakspot.wav` | `limb.m_type==Weakspot` 或 `precisionMulti>1.01` | 橙 X（×1.18） |
| 护甲命中 | `audio/bf5/armor.wav` | `limb.m_type==Armor`；`ArmorFromNoDamage=false` 时 `noDamage` 不算护甲 | 青色四角括号（×0.92） |

- 命中音与击杀音**各自独立节流**：`MinIntervalSeconds=0.05`。
- 有效音量 = `Volume × HitVolume × Gain × HitGain`；默认 `1.0 × 1.0 × 1.8 × 1.0 = 1.8`。
- `Style=BF1` 只改变普通命中；`BF6` 普通命中回落 BF5；弱点/护甲命中始终用 BF5 派生音。
- 素材缺失/解析失败时该次不响，但命中线仍画；不会静默吞掉原版反馈。

### 3.2 击杀音

| 档位 | 默认条件（`TierSource=EnemyType`） | 文件 |
| --- | --- | --- |
| MINOR | Weakling（`0`） | `audio/bf5/kill_minor.wav` |
| ELITE | Standard/Special（`1/2`） | `audio/bf5/kill_elite.wav` |
| BOSS | MiniBoss/Boss（`3/4`） | `audio/bf5/kill_boss.wav` |

- 飞行敌人：使用 `kill_flyer_*`；装甲飞行：`kill_armor_flyer_*`（P1 不画飞行徽记，但音效会选飞行 cue）。
- 风格回落链：
  - 请求风格（BF1/BF6）的 `kill_<tier>`/`kill_<flight>_<tier>`；
  - 再回落 `audio/bf5/<同名>`；
  - 再回落地面 `kill_<tier>`；
  - 再回落 `kill_minor`；
  - 最后回落 `audio/bf5/hit.wav`。
- BF1/BF6 只对 MINOR/ELITE（含飞行/装甲飞行）提供变体；BOSS 始终 BF5。
- 有效音量 = `Volume × KillVolume × Gain × KillGain`；默认 `1.0 × 1.0 × 1.8 × 1.6 = 2.88`。
- **击杀音高通**：`KillHighPassHz=350`，一阶高通削掉被枪声掩蔽的低频；`0` 关闭。
- 击杀音与命中音共用 `MinIntervalSeconds` 的击杀节流；连续击杀间隔小于 50 ms 时只保留一次。

### 3.3 独立击杀确认音（chime）

- 每次击杀在 BFV 击杀 cue 之外，额外叠一个**90 ms 合成高频确认音**：
  - 1700 / 2550 / 3400 Hz 三层正弦；
  - 400/s 快起音 + 48/s 指数衰减；
  - 独立 WinMM voice，不与命中音/霰弹音共享同一路。
- 配置：`KillChimeEnabled=true`、`KillChimeVolume=0.9`。
- 有效音量 = `Volume × KillChimeVolume × Gain ≈ 1.62`；tanh 软限幅。
- 击杀后 **150 ms 内跳过命中音**（`KillPriorityMs=150`），让击杀 cue/chime 不被霰弹或连续命中盖住。
- 若 `Sound/KillEnabled=false`，击杀 cue 与确认音都不播。

### 3.4 原版提示音

- `MuteVanillaIndicator=true` 时，通过 `CellSound.Post` 前缀跳过：
  - `BULLETHITENEMYLOCALINDICATOR`
  - `BULLETHITENEMYWEAKSPOTLOCALINDICATOR`
- `BULLETHITENEMYINDICATOR` 在当前构建里只存在于 `AK.BUSSES`，没有可解析的 event id，不静音。
- 只静音这三个提示事件；子弹冲击音、敌人受伤/死亡语音不受影响。
- 把 `MuteVanillaIndicator` 改 false 可恢复原版“叮”声，与自定义音效独立。

### 3.5 音频后端

- **WinMM `waveOut`**，8 个独立 device/voice；不经过 Unity `AudioClip`。
- 原因：本 IL2CPP 构建里 `AudioClip.Create/SetData` 反复抛
  `Il2CppSystem.ArgumentException`，原生异常风暴导致过崩溃。
- PCM 规格：48 kHz / 单声道 / 16-bit；峰值软限幅 `tanh`，避免硬削波。
- 设备打不开时只禁用声音并 5 s 后重试，不影响命中线/图标/游戏音频。

## 4. UI 出现时机

### 4.1 命中线

| 事件 | 图形 | 颜色 | 尺寸 | 生命周期 |
| --- | --- | --- | --- | --- |
| 普通命中 | `hitmark_normal.png` 白 X | `#FFFFFF` | `Size × 1.00` | 0.18 s |
| 弱点命中 | `hitmark_weakspot.png` X | `#FF8C00` | × 1.18 | 0.18 s |
| 真实护甲 | `hitmark_armor.png` 四角括号 | `#49ADC9` | × 0.92 | 0.18 s |
| 击杀 | `hitmark_kill.png` 加粗 X | `#B92828` | × 1.35 | 0.34 s |

- 世界锚点 = `ShowHitIndicator/ShowDeathIndicator` 上报的世界命中点；
  `Camera.WorldToScreenPoint` 投到 GUI，相机后方/屏幕外不画。
- `Size` 以 1080p 为基准，按 `Screen.height/1080` clamp 0.75–1.6。
- 同一敌人 50 ms 内的多次命中合并为一条：优先级
  `Kill > Weakspot > Armor > Normal`；击杀会把已有命中线升级成击杀线。
- 命中线队列上限 24；击杀线生命周期 0.34 s。
- 只有“成功画出替换线”时才抑制原版；素材缺失/相机为空/开关关闭时保留原版。
- `HitMarker/Enabled=false` 只关线，不影响击杀图标/音效；`ReplaceVanilla=false` 时原版保留、BFV 线叠加。

### 4.2 头顶击杀图标

| 档位 | 默认条件 | 图标 |
| --- | --- | --- |
| MINOR | Weakling（`EnemyType=0`） | `kill_minor.png` 白骷髅 |
| ELITE | Standard/Special（`1/2`） | `kill_elite.png` 橙骷髅 |
| BOSS | MiniBoss/Boss（`3/4`） | `kill_boss.png` 红齿轮 |

- 锚点 = 击杀瞬间的 `Owner.EyePosition + HeadGapMetres(0.35 m)`；取不到时
  命中点 + 0.6 m；锚点冻结，不随尸体下滑。
- 生命周期 2.2 s；淡入 0.1 s / 淡出 0.35 s；同屏最多 6 个，满时移除最旧。
- 尺寸 46 px @1080p，按屏幕高度缩放；整体透明度 0.85。
- P1 不做遮挡检测；相机后方/屏幕外不画；贴图缺失时该次不画图标，保留击杀线/音效。
- `KillIcon/TierSource=Health` 可回到 `HealthMax` 阈值模式：
  MINOR `<120`、ELITE `120–<1000`、BOSS `>=1000`。
- 为何默认 `EnemyType`：原生数据里 `Striker_Boss`（Boss，120 HP）、
  `Striker_Big`（MiniBoss，120 HP）、`Shooter_Big`（Boss，150 HP）按血量会被误判成 ELITE；
  类型模式才能稳定出红齿轮。

### 4.3 显隐/回退

- `FollowHudVisibility=true`：父血条 PageDown 隐藏时，命中线/图标/音效一起关闭，原版反馈恢复。
- `General/ToggleKey` 可临时关闭本 MOD；`General/Enabled=false` 完全恢复原版。
- 同时装 KillFeed 时先关它的 `HitSound`/`HitMarker`/`KillIcon`，避免双份反馈。

## 5. 配置速查

```ini
[General]
Enabled = true
ToggleKey = None
FollowHudVisibility = true

[Sound]
Enabled = true
Style = BF5
Volume = 1.0
Gain = 1.8
HitGain = 1.0
KillGain = 1.6
HitEnabled = true
KillEnabled = true
HitVolume = 1.0
KillVolume = 1.0
MinIntervalSeconds = 0.05
MuteVanillaIndicator = true
KillHighPassHz = 350
KillChimeEnabled = true
KillChimeVolume = 0.9
KillPriorityMs = 150
CustomDirectory = ""

[HitMarker]
Enabled = true
ReplaceVanilla = true
Size = 64
ColorNormal = #FFFFFF
ColorWeakspot = #FF8C00
ColorArmor = #49ADC9
ColorKill = #B92828
ArmorFromNoDamage = false
MergeWindowMs = 50

[KillIcon]
Enabled = true
Size = 46
Opacity = 0.85
Lifetime = 2.2
MaxIcons = 6
HeadGapMetres = 0.35
TierSource = EnemyType
MinorHealthThreshold = 120
HeavyHealthThreshold = 1000
```

P1 直接改 cfg 后重启生效；`CustomDirectory`/素材变更也建议重启。0.2.0 的
`PreLuna.ModControl` 0.3.4 面板对声音/命中线/图标/颜色/档位即时生效；颜色用
TheArchive 原生 `SColor` 拾色器，目标端仍校验 hex 后写入。

## 6. 验证与边界

- 2026-11-17 用户实机反馈 **“测试通过”**（0.1.0 整体通过，非逐项矩阵）：
  命中音、击杀音、独立确认音、高通、命中线、头顶图标与档位已一起测试。
- 0.2.0 新增面板/颜色控件，已安装并确认启动日志
  `BFV control=Available; settings=26; revision=1`；用户确认页面显示、26 项摘要压缩、
  颜色 Apply 即时变色、重启后读回均通过。
- 3 程序集构建通过；5 套离线测试共 **44 项**通过（BFV 10 + 控制 API 4）；
  ModControl 18 套离线测试通过（含 BFV 适配器 2 项）。
- 现装 DLL 与交付 SHA256 一致；WinMM 启动日志 `opened=True`、`base cues=6/6`、`icons=7/7`。
- 未单独覆盖：客机、真实 Armor 肢体的逐敌清单、长时间多波次、HD2 A/B、KillFeed 同装。
- 已确认/已知：
  - GTFO 没有可耗尽护甲池；`Armor` 只是 limb 类型 + `m_armorDamageMulti` 倍率。
  - 召唤的 `Striker_Big_Hibernate` 会出现游戏侧
    `ES_Hibernate.StartBeat/UpdateHeartbeat` 与 `ES_Hitreact.DoHitReact` 空引用，
    导致 0 血不死；与 BFV 反馈 MOD 无写血/死亡关系，需用非 Hibernate 变体对照。
  - 击杀音/确认音走独立 voice，但 WinMM 8 路全忙时会复用最旧 voice。
